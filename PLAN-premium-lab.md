# План платной секции Lab — архитектурный документ

**Дата:** 2026-06-03
**Автор:** Claude (по запросу Маши)
**Статус:** черновик для обсуждения, кода ещё нет

## Что Маша попросила (своими словами)

> Платный раздел в Lab. Кнопка «Платные уроки» сверху каталога. PIN или пароль не очень очевидный. Чтобы скачав код или клонировав GitHub-репо никто не получил доступа. Чтобы профи не «слили курсы». Элитный платный доступ, не дешёвая игрушка. Туда — Switzerland v2, Jerusalem, Voyager L1+L2 (всё что было сделано платными уроками с детьми).

## Главный технический вызов

Главный сайт `newgeneration-english.ru` хостится на **GitHub Pages**. Это статика. Никакого server-side кода. Любой JavaScript на странице **виден всем**. Любой пароль/токен/ключ в JS-коде → виден всем кто откроет DevTools или склонирует репо.

Поэтому **«просто PIN в JS» = не подходит.** Все варианты ниже решают эту дилемму по-разному.

## Три варианта архитектуры

### Вариант A — Только Supabase (наш текущий стек)

**Как работает:**
- Кнопка «Платные уроки» в Lab → переход на `lingua-boost-lab/premium.html`
- На странице — форма PIN
- При submit JS отправляет PIN в **Supabase Edge Function** `verify-premium-pin`
- Function проверяет PIN из **Supabase secrets** (не в коде сайта)
- Возвращает **signed URLs** уроков из приватного Supabase Storage bucket (`premium-lessons`)
- JS рендерит карточки с временными ссылками (TTL 7 дней)

**Где живут уроки физически:**
- `Supabase Storage` приватный bucket
- Внутри: `switzerland-v2/index.html`, `jerusalem/index.html`, `voyager-l1/index.html`, и т.д. + все картинки/аудио

**Безопасность:**
- 🟢 PIN не в коде сайта (в Supabase secrets)
- 🟢 Уроки не в репо (в приватном Storage)
- 🟢 Склонировал репо → видит только landing + JS-запрос к Supabase
- 🟢 Signed URLs одноразовые с TTL
- 🟡 Один утёкший PIN → доступ ко всему на 7 дней. После TTL — снова просим PIN.

**Стоимость:**
- 🟢 Supabase Free tier хватит надолго (1 ГБ Storage, 50 ГБ bandwidth)
- 🟢 Edge Functions бесплатно до 500K invocations/мес

**Работа:**
- Edge Function на TypeScript (Codex напишет за 1 час)
- Storage bucket + RLS-политики (30 мин)
- Миграция уроков в Storage (1-2 часа, можно автоматизировать)
- Frontend `premium.html` (1-2 часа)
- **Итого: 1 день инженерии**

---

### Вариант B — Cloudflare Workers (новая инфра)

**Как работает:**
- Кнопка «Платные уроки» → ведёт на отдельный поддомен `premium.newgeneration-english.ru`
- Этот поддомен обслуживает **Cloudflare Worker** (не GitHub Pages)
- Worker проверяет PIN (хранится в Worker secrets)
- Уроки лежат в **Worker KV storage** или **R2 bucket**
- Worker отдаёт HTML урока напрямую (без редиректов)

**Безопасность:**
- 🟢 Всё то же что у А
- 🟢 Дополнительно: уроки физически не доступны без Worker
- 🟢 Можно добавить rate limiting на edge

**Стоимость:**
- 🟢 Workers Free tier: 100K запросов/день
- 🟢 R2 бесплатно до 10 ГБ + 1M requests/мес

**Работа:**
- Новая инфраструктура (Маша ещё не работала с Workers)
- Worker на JS (Codex может, но это новый код)
- Миграция уроков в R2 (Wrangler CLI)
- DNS-запись `premium.newgeneration-english.ru` → Worker
- **Итого: 1-2 дня инженерии + новая зона обучения**

---

### Вариант C — Cabinet-based (минимум новой инфры)

**Как работает:**
- Кнопка «Платные уроки» в Lab → переход на `cabinet.newgeneration-english.ru/premium`
- Это новая страница в существующем кабинете
- Кабинет уже использует Supabase Auth + PIN
- В `data.js` (или Supabase) у студента поле `premium_access: true`
- При логине по PIN кабинет показывает раздел «Платные уроки» только тем у кого premium

**Безопасность:**
- 🟢 Использует уже работающую auth-инфру
- 🟢 PIN-flow знаком ученикам
- 🟡 Уроки могут лежать в `nge-cabinet` репо (приватный, на Cloudflare Pages) — это OK, репо не публичный
- 🟢 Или в Supabase Storage с signed URLs (как в варианте А)

**Стоимость:**
- 🟢 Вся инфра уже куплена/настроена
- 🟢 Никаких новых сервисов

**Работа:**
- Новая страница `cabinet/premium.html` (4 часа)
- Поле `premium_access` в data.js / Supabase (1 час)
- Уроки скопировать в `nge-cabinet` репо ИЛИ Storage (1-2 часа)
- **Итого: полдня инженерии**

**Минус для Машиной идеи:**
- Платная секция технически живёт в **кабинете**, а не в **Lab**. То есть «элитный платный доступ» брендируется как «премиум-кабинет», не как «премиум-лаборатория». UX-смесь.

## Моя рекомендация — **Вариант A** (Supabase) для production. Стартуем через A.

**Почему A, не C:**
- Маша явно сказала «**в Lab**» делать платный раздел, не в кабинете. UX-консистентность важна.
- Supabase Storage даёт чистый брендинг `lingua-boost-lab/premium`.
- А переходит в кабинет — это другой ментальный путь у юзера.

**Почему A, не B:**
- Supabase уже работает у нас, Workers — новая инфра.
- Storage signed URLs ≈ R2 signed URLs по безопасности.
- Меньше surface для багов.

## Минимальный путь MVP (если возьмём A)

Это то что мы сделаем на следующей сессии когда ты дашь ответы.

**Этап 1 — Инфра (Codex или я)**
- Создать Supabase Edge Function `verify-premium-pin`
- Создать private Storage bucket `premium-lessons`
- Загрузить туда 4 урока (Switzerland v2, Jerusalem, Voyager L1+L2 + их assets)
- RLS-политики: только anonymous insert (для analytics), read только с signed URL
- Прописать PIN(ы) в Supabase secrets

**Этап 2 — Frontend (я)**
- Создать `lingua-boost-lab/premium.html` (landing + форма PIN)
- Скрипт: PIN → fetch к Edge Function → получить список signed URLs
- Если success — рендер карточек с кнопками «открыть урок»
- Если fail — error message с подсказкой «не туда попал»

**Этап 3 — Кнопка в Lab (я)**
- В `lingua-boost-lab/index.html` добавить карточку «🔒 Платные уроки» сверху
- Стиль: золотая, с пометкой «доступ по приглашению»

**Этап 4 — Запуск**
- Маша создаёт первый PIN (выдаёт реальному ученику/коллеге)
- Тестируем end-to-end
- Готово к публикации
